# Office interop oracle

MarkDownIt imports and exports Word documents and exports PDF. This directory
holds the measurement harness for that work: fixtures produced by independent
tools, goldens read back by independent readers, and checkers that compare a
file produced by MarkDownIt against those goldens.

The idea is simple. python-docx and reportlab write the reference files. pypdf
and python-docx read them back and record what they see. MarkDownIt then has to
agree, in both directions: its Word importer must extract what python-docx
extracts, and its Word and PDF exporters must write files that these readers
accept as equal to the reference.

Nothing here is hand-written. Every file under `tests/office/` is generated by
`make_fixtures.py`, and a CI job fails when the committed copies no longer
match what the generator produces.

## Contents

| Path | Purpose |
| --- | --- |
| `make_fixtures.py` | Deterministic generator for the fixtures and the goldens |
| `dump_docx.py` | Independent Word reader (python-docx) to JSON |
| `dump_pdf.py` | Independent PDF reader (pypdf) to JSON |
| `docx_to_md.py` | The reference .docx to Markdown mapping |
| `check_docx.py` | Compares a produced .docx against `reference_docx.json` |
| `check_pdf.py` | Compares a produced .pdf against `reference_pdf.json` |
| `check_drift.py` | CI gate: committed fixtures and goldens versus regenerated ones |
| `requirements.txt` | Pinned oracle dependencies |

Generated, committed, never edited by hand:

| Path | Content |
| --- | --- |
| `tests/office/fixtures/reference.docx` | Reference Word document |
| `tests/office/fixtures/reference.pdf` | The same content as a 2-page PDF |
| `tests/office/fixtures/large.docx` | 240 sections, an estimated 259 Word pages |
| `tests/office/golden/reference_docx.json` | python-docx content model of `reference.docx` |
| `tests/office/golden/reference_pdf.json` | pypdf page dump of `reference.pdf` |
| `tests/office/golden/reference.md` | `reference.docx` through the Markdown mapping |
| `tests/office/golden/large_docx.json` | Block count, heading count, page estimate |

## The reference content

`reference.docx` and `reference.pdf` carry the same material:

- title `MarkDownIt Office Interop Reference`
- Heading 1 `Indledning`, then a paragraph with a bold run, an italic run, a
  monospace run (Consolas), an underlined run and Danish characters
  (`æ ø å Æ Ø Å`)
- Heading 2 `Punktliste`, a bullet list of three items where the second item
  has a nested sub-item, then a numbered list of three items
- Heading 2 `Tabel`, a 3x3 table with a `Navn / Antal / Note` header row and
  Danish cell text
- a hyperlink to `https://example.com`

The Word file uses A4 portrait and 2 cm margins on all sides. The PDF uses A4
portrait, forces a page break after the lists, and prints a `Side N` footer on
every page.

## Regenerating

```
python3 -m venv .venv-oracle
.venv-oracle/bin/pip install -r tools/office-oracle/requirements.txt
.venv-oracle/bin/python tools/office-oracle/make_fixtures.py
```

The generator writes into `tests/office/fixtures` and `tests/office/golden` by
default and prints the sha256 of every file it writes. Use `--fixtures-dir` and
`--golden-dir` to write somewhere else, which is what CI does.

Regenerating is only correct when the change is intentional. Commit the
regenerated files together with the generator change that caused it. Never edit
a golden by hand: change the generator and regenerate.

## Determinism

Byte-identical output across runs is a hard requirement, because CI compares
regenerated files with the committed ones. Both libraries stamp wall-clock
time into their output by default, so the generator neutralizes that:

- Word core properties get fixed timestamps (`2020-01-01T00:00:00Z`), a fixed
  author and revision 1.
- The docx package is rewritten after python-docx saves it: members sorted by
  name, deflate level 9, timestamps fixed at `1980-01-01`, fixed external
  attributes. This also drops the template thumbnail part, so the fixture
  carries no images at all.
- The PDF is built in reportlab invariant mode with `pageCompression=0` and a
  fixed build timestamp, and `SOURCE_DATE_EPOCH` is ignored for the duration of
  the build. No clock value and no zlib version can reach the file.
- The page estimate for `large.docx` comes from the document's own style
  metrics (`estimate_large_pages` in `make_fixtures.py`), so the "over 200
  pages" claim is a number the generator checks before it writes anything.

`check_drift.py` compares sha256 first. If the compressed bytes of a .docx or
.pdf differ while the decompressed content is identical, it reports a warning
instead of an error, since that is a toolchain artifact rather than drift. Any
real content change, a missing file, or an unreadable file fails the job with a
`::error::` annotation naming the file.

## Checking a produced file

```
.venv-oracle/bin/python tools/office-oracle/check_docx.py path/to/produced.docx
.venv-oracle/bin/python tools/office-oracle/check_pdf.py path/to/produced.pdf
```

Both exit 0 on a match. On a mismatch they exit 1 and print a unified diff of
the first differences: one line per block, run and table row for Word, one
diff per page for PDF. Text is normalized before comparison. Runs of whitespace
collapse, so run splits do not matter. PDF pages compare as non-whitespace
character sequences, so line breaking and kerning do not matter. Page sizes
have a 1 point tolerance, page setup in Word has 0.01 pt.

The Word comparison trusts only direct run formatting. A run is bold, italic,
underlined or monospace when the run itself says so, and style-inherited
formatting is not resolved. The monospace font names that count are listed in
`dump_docx.py`.

## The Markdown mapping

`docx_to_md.py` is the contract for Word import. Title becomes `# `, Word
Heading 1 becomes `## ` (the title owns the first level), bullets become `- `,
ordered items are numbered from 1 inside each list, nesting is two spaces per
level, and tables become GFM pipe tables with the first row as the header.
Bold, italic and monospace runs become `**x**`, `*x*` and `` `x` ``, links
become `[text](url)`, and underline has no Markdown equivalent, so it is
dropped. The full rules are in the module docstring, and
`tests/office/golden/reference.md` is the mapping applied to the fixture.

## In CI

The `office-oracle` job in `.github/workflows/build.yml` runs on every push:

1. regenerate the fixtures and goldens into `/tmp/office-oracle`
2. run `check_drift.py` against the committed trees, failing the job with a
   `::error::` annotation that names every drifted file
3. upload the regenerated directory as the `office-oracle` artifact, always,
   so a red run still leaves the evidence behind
