# Outline Pane Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task. Subagents never commit or push; the coordinator runs every gate and does all git work.

**Goal:** A left-side Outline pane in MarkDownIt that shows the document's heading hierarchy, highlights the active heading, and navigates on click, per `references/outline-pane-view.md`.

**Architecture:** Three layers. (1) A portable, headless outline model (`src/outline.h/.cpp`, no windows.h, local g++ testable) that mirrors the DOM heading list plus pure collapse/filter state machines. (2) An `OutlinePane` docked as a left-side child HWND following the `FindBar` precedent: own window class and WndProc, geometry managed by `ResizeContentWindow`, painted welcome-screen-style with D2D on its own small HwndRenderTarget. The document window keeps its full coordinate space (hwnd_content_ moves right and shrinks), so scroll ranges, mouse hit-testing and the search-fill path stay untouched. (3) App wiring: a View-tab ToggleButton toggles the pane, navigation composes the proven `OpenLink` anchor jump (edit mode: sel_.Collapse + UpdateCaretPosition; view mode: scroll-only BlockForOffset + StartSpring), and the outline refresh hooks the existing reparse path (incremental parse, `ScheduleReparse`/`OnReparseTimer`) rather than adding a second parse.

**Tech Stack:** C++17, Win32 child window message loop (existing `hwnd_content_`), Direct2D/DirectWrite (existing `rt_`), md4c DOM. Tests: `tests/gtest_lite.h`, portable parts under local g++ 15.2.0 in WSL, full build gate via GitHub Actions CI (windows-2022).

**Verified codebase facts** (do not re-derive; subagent research corroborates):
- `src/dom.h`: `Node { BlockKind block; int level /* heading 1-6 */; std::vector<InlineBlock> children; uint32_t srcOffset, srcLength, contentOffset, contentLength; }`. Heading nodes carry level in `Node::level`; inline text lives in `children` as UTF-32 `InlineBlock::text` spans. No parser changes needed.
- Welcome screen pattern: `WelcomeScreen` object owned by `AppWindow` (`welcome_`), `Init(dw_factory_)` creates DWrite formats, `Layout(viewW, viewH)` computes card rects in DIPs, `Render(rt, ...)` paints on the shared `rt_`, `HitTest(x, y)` informs `OnLButtonDown`. Rendered inside the content window's WM_PAINT (app.cpp ~3107-3122). This is the pattern to copy.
- Content window layout: `ResizeContentWindow()` (app.cpp 2694) positions `hwnd_content_` under the ribbon and docks the find strip. The pane is the same pattern on the left: hwnd_content_ moves to x = paneW and loses paneW of width; scroll ranges follow through the clientW_ chain.
- FindBar is the windowing precedent (own HWND, own WndProc, parent-owned, `find_bar_.Dock()`; tests/findbar_window_test.cpp shows what is testable headlessly). The pane copies this plumbing.
- Heading-jump precedent: `OpenLink`'s #anchor path (app.cpp 1312-1333) walks Heading nodes, slug-matches, then BlockForOffset + StartSpring. View-mode jumps are scroll-only; edit-mode jumps set the caret.
- Render-target evidence: OnCreate's comment (app.cpp ~2570-2572) records why each D2D surface lives on its own child window (a shared-HWND present overwrites sibling UI, the ribbon bug). The pane's own HwndRenderTarget follows that rule.

```cpp
#pragma once

// Outline model: the heading navigation projection of the document DOM.
// Portable and headless (no windows.h) so it builds and tests under g++.
// The pane keeps no second document copy; it borrows the Document after
// each reparse and derives its item list.

#include <vector>
#include <string>
#include <cstdint>
#include "dom.h"

// One outline entry, in document order.
struct OutlineItem {
    int          level = 0;      // heading level 1..6
    uint32_t     offset = 0;     // source byte offset of the heading start
    std::u32string text;         // simplified plain text of the heading
};

// Collect all heading nodes in document order. Simplification: inline
// spans of any kind contribute their plain UTF-32 text only; images
// contribute their alt text. Returns an empty vector when no headings.
std::vector<OutlineItem> CollectHeadings(const Document& doc);

// Plain text of one item (helper exposed for tests).
std::u32string ConcatenateInlineText(const OutlineItem& item);
```

**Step 4: Implement `src/outline.cpp`** iterating `doc.nodes`, selecting `BlockKind::Heading`, reading `node.level`, `node.contentOffset`, and concatenating `children` UTF-32 text (replace an `Image` span's text with nothing; link text stays). Keep it under 80 lines.

```cpp
// Which branches the user collapsed, keyed by item index. Persisting this
// across reparses is a later store; here it is pure state.
struct OutlineCollapse {
    std::set<int> collapsed;
    void Toggle(int idx) { /* insert or erase */ }
    bool IsCollapsed(int idx) const;
};

// Visible item indices given the collapse state. An item is hidden when
// any ancestor branch (strictly shallower heading earlier in the list,
// up to the nearest ancestor by level) is collapsed.
std::vector<int> VisibleItems(const std::vector<Item>& items,
                              const OutlineCollapse& st);

// The heading owning the byte offset: the last heading whose start offset
// is <= offset (spec 6.1 / 21). -1 when offset precedes all headings.
int ItemIndexForOffset(const std::vector<OutlineItem>& items, uint32_t offset);
```

```cpp
public:
    bool Create(HWND parent, HINSTANCE hinst);      // own window class, own WndProc

private:

    // WM_PAINT: own rt_, pane bg + separator + rows + disclosure triangles + empty state (spec 17/24)
```
