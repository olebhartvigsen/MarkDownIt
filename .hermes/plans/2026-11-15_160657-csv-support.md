# CSV support: a table document in the same engine

Status: S1 to S4 are built (parser, bridge, fixed font, numeric alignment,
open path, per-column filters). S5 and S6 are specified below and not built
yet.

## What this adds

A `.csv` (and `.tsv`) file opens as a **table document**: the file's rows
drawn by the same table view markdown already has, in a fixed font, with a
filter control on every column header. The file is a viewer: no markdown
formatting, no table editing, no saving. A spreadsheet is a spreadsheet
program's job; this app's job is to read one that arrived next to a folder of
markdown files.

The page is a document, not a new surface: the same title bar, the same file
watch, the same scroll, the same command table with the commands that need a
markdown buffer greyed, the same home screen card.

## What we reuse, and why nothing new is drawn

The whole render path is already there:

| Step | File | Reused as is |
|------|------|--------------|
| Node list | `src/dom.h` | `BlockKind::Table`, `TableRow`, `TableCell`, `ColumnAlign` |
| Layout | `src/layout/table_layout.cpp` | `LayoutTableBlock`: column split by longest word, row heights, zebra, grid, header fill |
| Display list | `src/layout/displaylist.h` | the table's fills and the block record |
| Painting | `src/renderer.cpp` `DrawTable`, `src/macos/renderer_mac.cpp` `PaintTableOverlays` | the measured per-cell lines, clipped and aligned |
| Document | `src/documentcontroller.*` | one buffer, one parse, one undo stack |
| File | `src/documentfile.*` | BOM, CRLF, decode and encode |
| Watch, title, recents | `app.cpp`, `main_mac.mm`, `settings.*` | unchanged |

So the work is: **produce a `Document` whose single node is a table**, and
teach the table view three things it does not know yet (a fixed font, a
header affordance, a filtered row set).

## Research

### The format

RFC 4180 is the only written spec, and it is thin. What a reader has to
survive in the wild:

- Fields may be quoted with `"`; inside, `""` is one quote; a delimiter or a
  line end inside quotes is data, not structure.
- Line ends are CRLF by the spec, LF and CR in practice, and a file can mix
  them.
- A UTF-8 BOM is common, because Excel writes one, and UTF-16 with a BOM
  turns up from the same source.
- The delimiter is not always a comma: `;` where the comma is the decimal
  mark, tab in `.tsv`, `|` in some exports.
- Rows are ragged: a short row, a trailing empty field, a stray blank line.
- Numbers carry thousands separators, currency marks, percent signs, and
  parentheses for negatives.
- The first row may or may not be a header; bank exports often have none.

### What good viewers do

From Rainbow CSV, csvlens, Modern CSV, Excel's filter dropdown, Numbers,
DuckDB's CSV reader, and the two data-table design guides found in the
research (Pencil and Paper, and the "Ultimate Guide to Designing Data
Tables"):

- **Filters live in the column header**, not in a toolbar: a funnel on the
  header opens that column's distinct values with checkboxes and a search
  box, plus Select all and Clear. Excel's dropdown is the model every reader
  has already met.
- **Numbers right, text left, and the header follows its column.** Never
  centre a column of values.
- **Tabular or monospaced figures.** A proportional font makes `9` wider than
  `1`, so `999.99` looks smaller than `1,111.11`. The request for a fixed
  font for the data is that rule taken further: in a file of unknown shape,
  the column count wins over prose typography.
- **Delimiter sniffing** from the extension first and the content second:
  split the first lines by each candidate and take the one whose per-line
  field count is most consistent.
- **Header detection is a guess**, and the reader gets a switch to say so.
- **Row numbers** let a reader talk about a row ("row 431"), which matters
  more in a CSV than in prose.
- **Large files**: sample the first rows to size columns, and never build a
  view of a million rows up front.
- **An empty cell is not a missing column**: a trailing delimiter is an empty
  field, not an error.

### What we take, and what we leave

Taken: RFC 4180 quoting, BOM, CRLF/LF/CR, delimiter sniff with an extension
hint, ragged rows padded, a header row with a filter control per column, a
fixed font, numeric columns right-aligned, the header aligned with its
column, a row-number gutter, a row cap with an honest notice, and a header
switch.

Left out of this change: editing and saving CSV (quoting round-trips are
their own project), sorting, formulas, multi-file joins, UTF-16 decoding
(reported, not guessed), locale decimal commas in numeric detection (a cell
like `1,25` stays text), and registering `.csv` as the system handler, which
would take the file away from the reader's spreadsheet.

## Design

### 1. Parsing, shared: `src/csv.h`, `src/csv.cpp`

```cpp
namespace csv {
struct Table {
    std::vector<std::vector<std::string>> rows;   // UTF-8, padded to the widest row
    char delimiter = ',';
    bool hasHeader = false;
    std::size_t sourceRows = 0;                   // rows the file held
    bool rowsTruncated = false;
    bool columnsTruncated = false;
    bool cellsTruncated = false;
    bool unsupportedEncoding = false;             // UTF-16 and the like
};
// hint is 0 to sniff, or the delimiter to force (.tsv passes '\t').
Table Parse(const std::string& utf8Text, char hint = 0);
}
```

Rules, in order:

1. Strip a UTF-8 BOM. A UTF-16 or UTF-32 BOM returns an empty table with the
   encoding flag set, so the window can say the encoding is unsupported
   instead of showing noise.
2. Sniff the delimiter when there is no hint: `,` `;` `\t` `|`, scored on the
   first 20 records by how consistent the field count is, with `,` winning
   ties.
3. Split records: a record ends at CR, LF or CRLF **outside** quotes; a
   quoted field keeps its delimiters, its line ends and its `""`.
4. Pad every row to the widest row.
5. Decide the header: the first row is a header when it has no cell that
   parses as a number, at least one non-empty cell, no duplicate cell, and
   the file holds at least two rows. The reader can flip it (S5), because a
   guess is a guess.
6. Caps: 64 columns, 20,000 rows, 1 MiB per cell. Each cap sets its flag.

The parser has no file API, no window and no platform header, so it runs in
the portable tests and on both ports unchanged.

### 2. The bridge: `src/csvdocument.h`, `src/csvdocument.cpp`

```cpp
namespace csvdoc {
bool IsCsvPath(const std::string& pathUtf8);        // .csv, .tsv, .tab
char DelimiterHintForPath(const std::string& pathUtf8);
Document BuildDocument(const std::string& utf8Text,
                       const std::string& pathUtf8);
}
```

`BuildDocument` returns a `Document` with:

- one `BlockKind::Table` node, the first row flagged `isHeader` when a header
  was found, every cell decoded to UTF-32;
- `Node::tableMonospace = true`, the new flag the table layout reads to pick
  the code font;
- `aligns[c] = Right` for a column whose non-empty body cells are numbers
  (leading sign, digits, one decimal point, an optional exponent) in at
  least 80 percent of its rows, otherwise `Left`;
- one trailing `Paragraph` node when something was capped, in the reader's
  words: "Showing the first 20,000 of 120,000 rows." Nothing is silent.

### 3. The fixed font, decided in one place

`LayoutMetrics` already names a code font (`THEME_CODE_FONT`: Cascadia Mono
on Windows, Menlo on the mac through the style). `Node` gets one flag:

```cpp
bool tableMonospace = false;   // a table that holds data, not prose
```

`BuildCellRuns` in `src/layout/table_layout.cpp` picks `m.codeFont` and a
size that fits the cell padding when the flag is set, so the measured lines
carry the code font and both port painters, which draw those runs, follow
without a change of their own.

### 4. Filters in the header row

**The model is shared**: `src/csvfilter.h`, `src/csvfilter.cpp`.

```cpp
class FilterModel {
public:
    void Build(const csv::Table& table);         // distinct values per column
    bool Active() const;
    std::size_t VisibleRows() const;
    const std::vector<std::string>& Values(std::size_t column) const;
    std::vector<std::string> Matching(std::size_t column,
                                      const std::string& query) const;
    bool Selected(std::size_t column, const std::string& value) const;
    void SetSelected(std::size_t column, const std::string& value, bool on);
    void SelectAll(std::size_t column);
    void Clear(std::size_t column);
    void ClearAll();
    std::vector<std::size_t> Rows() const;       // file order, header excluded
};
```

The parse, the filter and the visible row set live in one place the
controller owns. Re-filtering rebuilds the table node from the cached parse
and re-lays it out, the same path an edit takes. Column values are capped at
500 distinct entries, with the true count kept so the surface can say "500
of 1,240 values".

**The control is native, the list is shared.** The header cell draws a funnel
at its right edge, from primitives in `table_layout.cpp`, plus a tint when
the column is filtered. `LaidTable` gains the header cell rects, so a shell
asks `csvview::HeaderFilterAt(x, y)` for the column under a press. Each shell
then opens its own native surface, built from `FilterModel`:

- macOS: an `NSPopover` under the funnel holding an `NSSearchField`, an
  `NSTableView` of checkable rows, and Select all / Clear. The toggles call
  the model and the window re-filters.
- Windows: an owned popup window with an `EDIT` for the search and a
  `ListView` with `LVS_EX_CHECKBOXES`, the same three actions.

Both are chrome, both read the same model, so no rule about filtering is
written twice.

### 5. The window, the file and the commands

- **Kind**: `.csv`, `.tsv` and `.tab` join `.md`, `.mmd` and `.svg` in the
  open dialog filters, the drop handler, the file watch and the recent list.
  `documentfile` gains `FileFormat::isTable`, so the file's BOM and line ends
  survive a reload unchanged (there is no save).
- **Read-only**: `commands::Context` gains `tableDocument`. The mutating
  commands, the table editing commands, the inline formatting and Find all
  stand down there, the way they do on a diagram. `RequirementsOf` gets its
  rows and `tests/commandstate_test.cpp` holds them. View mode is the only
  mode; there is no Edit switch.
- **Title, recents, watch**: the existing paths, driven by the path.
- **Home card**: a `.csv` card shows its first rows as text, because the
  preview is already text; the card's kind badge says `CSV`.

### 6. Limits, and speed that stays honest

- Rows: 20,000 parsed, and the notice says so. The layout of one table block
  measures every cell, so the cap is what keeps opening a file under a
  second. The number is measured, not guessed: S5 adds the benchmark.
- Columns: 64. A 4,000-column export is a machine's file.
- Cell text: 1 MiB, then truncated with an ellipsis and the flag.
- **Painting** walks the whole laid block today. S5 adds a visible row range
  to `LaidTable`, driven by the viewport, so both painters draw only the rows
  on screen. Until then the row cap is the guard.
- Filtering rebuilds the table node. At 20,000 rows that is one vector copy
  per filter change, measured in the same benchmark.

## Risks and open questions

- **Quoting round-trips** are why saving is out of scope: a cell that held
  `"a,b"` and one that held `a,b` look alike once written back. Read-only
  until that project.
- **Header guessing** will be wrong on some files. The switch in S5 is the
  answer, not a better guess.
- **Delimiter ambiguity**: a one-column file of semicolons is a judgement
  call. The sniff prefers consistency, and the reader can flip it later.
- **Filters and Find**: Find searches the text buffer and the table paints
  its own cells, so a find highlight cannot land in a cell. Filters are the
  search a table needs; Find stays off in a table document, and
  `references/csv-view.md` says so.
- **Numbers** follow the plain form only. A locale that writes `1,25` gets a
  text column, which is wrong but honest; the follow-up reads `;`-delimited
  files as comma-decimal when the delimiter is `;`.
- **The 20,000 row cap** is a product decision, not a technical one, and it
  now has numbers behind it: the table lays out every row up front, so
  20,000 rows x 12 columns costs 27 ms to parse and 201 ms to lay out with
  the fake engine, and a platform text engine costs more than that. Every
  re-layout (zoom, resize) pays it again, which is why S5's visible-row
  painting is the thing that lifts the cap rather than a bigger number
  here.
