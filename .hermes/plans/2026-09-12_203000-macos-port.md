# MarkDownIt: macOS port implementation plan

> Intended for: an agent picking this up, or the user driving the port.
> Goals and architecture background: references/macos-build-pipeline.md
> Windows side: do not touch windows-only files. The Windows app stays the
> reference product; the mac port is a parallel UI layer on the shared core.

**Goal:** A native macOS app (Cocoa + Core Graphics + Core Text, zero
shipped dependencies) that opens and renders the same markdown with the
same editor features as the Windows app, reusing the portable core.

**Core constraint:** macOS UI code compiles only on macOS (this container
has no Cocoa headers and no C++ toolchain). Verification per task below
tells you where each piece can actually be checked.

## Shared core (transfer as-is, do not modify)

`dom.h`, `textbuffer.*`, `caret.h`, `editcontroller.*`, `undostack.*`,
`formatting.*`, `autoformat.*`, `inputfilter.*`, `svgtext.*`, and all of
`src/mermaid/*` except `measure_dwrite.cpp`. These contain no Windows
headers and no `std::wstring` (verified by grep).

Two shared files are NOT copy-as-is, and one pair needs the Task 1 stub:

- `parser.cpp`: portable parsing except the `ParseMarkdown` crash guard,
  which uses Win32 structured exceptions (`__try`/`__except
  (EXCEPTION_EXECUTE_HANDLER)`) and `CreateFileA`. The guard goes behind
  `#ifdef _WIN32` (Task 1). This is the only MSVC-only syntax in the
  shared set.
- `theme.h`: includes `<d2d1.h>` (`D2D1_COLOR_F` colors) and two
  `const wchar_t*` font names. The mac target needs a plain 4-float RGBA
  struct and `std::string` font names (Task 2).
- `navigation.*` builds against `layoutcache.h`, which includes
  `<dwrite.h>`; the stub header in Task 1 covers that include chain.

## Task 1: Native test gate (macOS CI can run the whole suite)

The test target links only `md4c` and compiles app sources including
`layoutcache.cpp`, `navigation.cpp`, `parser.cpp`, `clipboard.cpp`, and
all portable mermaid files. No test calls any DirectWrite function
(verified: zero matches in tests/), so compile-time stubs are enough.

- Create `tests/stubs/dwrite.h`: define `IDWriteTextFormat` and
  `IDWriteTextLayout` as minimal interface shells, plus the other types
  layoutcache.h references (e.g. `DWRITE_HIT_TEST_METRICS`).
  layoutcache.cpp itself never calls DirectWrite (verified: zero
  `IDWrite` matches), so names alone suffice. Methods declared, never
  called by tests.
- `CMakeLists.txt`: when `APPLE AND BUILD_TESTS`, prepend `tests/stubs` to
  the test target include path. Do not touch the MSVC branches.
- `parser.cpp`: guard the `ParseMarkdown` crash-log block
  (`__try`/`__except(EXCEPTION_EXECUTE_HANDLER)` with
  `CreateFileA`/`WriteFile`, around lines 751-775) behind
  `#ifdef _WIN32`. This is Windows structured-exception syntax; macOS
  clang cannot compile it. It is the only non-header change the test leg
  needs.
- Workflow: add a `test-macos` job, `runs-on: macos-15-arm64` (Apple
  silicon). Do not use macos-14: those images are deprecated and
  unsupported after November 2, 2026.

```yaml
  test-macos:
    name: Tests (macOS, portable core)
    runs-on: macos-15-arm64
    steps:
      - uses: actions/checkout@v4
      - name: Configure
        run: cmake -B build-native -DBUILD_TESTS=ON
      - name: Build and run
        run: |
          cmake --build build-native --target MarkDownIt.tests
          ./build-native/MarkDownIt.tests
```

**Verify:** the whole suite (221 tests: parser, editor, undo, formatting,
all mermaid golden tests, svgtext) passes natively on Apple Silicon. Run
it at least once before any port code lands, so the gate is green before
changes start.

**Pitfall:** `clipboard.cpp` compiles on mac as-is (Win32 half behind
`#ifdef _WIN32`, and `clipboard.h` already has `typedef void* HWND` for
non-Windows); `clipboard_test.cpp` only calls the portable escape/convert
helpers. `settings.cpp`, `fileassoc.cpp`, `filewatch.cpp` are NOT in the
test target; they are Windows-only and stay that way until Tasks 6-7.

## Task 2: Repository skeleton for the mac target

- New dir `src/macos/`. CMake: `if(APPLE)` branch that builds a
  `markdownit_core` static library from the shared sources plus the mac
  implementations, and the `MarkDownItMac` executable (later renamed to
  MarkDownIt in the bundle).
- `theme.h` adaptation: replace `D2D1_COLOR_F` with a plain 4-float RGBA
  struct and the `wchar_t` font names with `std::string` so no mac target
  includes `<d2d1.h>`. Fonts: "Segoe UI" does not exist on mac; use the
  system stack (body: system UI font; code: Menlo/Monaco) in the mac theme
  variant, not in theme.h.
- Create `src/macos/seams.h`: the three narrow interfaces the port code is
  written against:
  - `TextEngine`: `MeasureWrapped(text, fontSpec, maxWidth, lineSpacing) ->
    lines{width,height,glyphRuns}`, `HitTestOffset(line, x) -> utf8
    offset`, `OffsetToRect(line, offset) -> {x,y,width,height}`.
  - `RenderTarget`: fill rect, fill rounded rect, stroke line, draw text
    with per-run color, push/pop clip, draw bitmap.
  - `AppShell`: window, invert rect, timers, focus, cursor, menus,
    clipboard, open-in-browser.
- Keep the Windows side untouched. The seams are for the mac layer only;
  retrofitting renderer.cpp to use them is optional later, not part of this
  port.

**Verify:** compiles on the Mac (or CI macos-15-arm64). Nothing runs yet
beyond a blank window; that is Task 3.

## Task 3: Skeleton window: open, parse, render text

- `src/macos/main_mac.cpp`: NSApplication, open the file passed as argv or
  dropped on the dock icon, hand the path to the app object.
- `src/macos/app_mac.cpp` + `content_view_mac.cpp`: NSView subclass with
  `drawRect` that renders the parsed Document with CG; mouse wheel scrolls
  (reuse the existing spring physics code by porting the state machine
  from app.cpp, it is pure math once the timer is Cocoa's); window resize
  re-layouts.
- Text rendering: renderer_mac.cpp with the smallest viable slice:
  headings, paragraphs, inline text without styling, scrolling, correct
  wrapping width. This task proves the CG/CT translation, DIP handling,
  and the parse path end to end.
- Port `parser.cpp` bridge usage as-is: `ParseMarkdown(utf8, doc_)` is
  already platform-free once the SEH guard from Task 1 is in place.

**Verify:** on the Mac: `MarkDownItMac sample.md` shows the document,
scrolls, wraps, and matches the Windows layout for the same file (compare
screen distance, not pixels; fonts differ by design). On CI: test suite
still green (this task touches no shared code, so it should be).

**Pitfalls:**
- macOS `wchar_t` is 4 bytes. Do not use `std::wstring` in mac code. The
  shared core uses `std::string`/`std::u32string`; convert at the edges.
- DPI: the Windows code converts DIPs to pixels via `dpi_`. On mac, CG
  renders in device pixels and Cocoa reports the scale; keep the layout in
  DIPs and scale once in the CG context, same formula as today.

## Task 4: Renderer parity (all block types and inline styles)

Port the rest of renderer.cpp against the mac seams:
- Tables (reuse `MeasureTable` geometry; the Windows renderer's
  row-measuring loop is already extracted and portable).
- Fenced code blocks (background, border, rounded rect), blockquotes
  (bar + indent), lists (marker as separate layout, indentation), thematic
  breaks, code color + background.
- Inline styling: bold, italic, code, strikethrough via CT attributed
  runs. Link color via per-run CG drawing state (the ColorTextRenderer
  effect mechanism becomes a per-run color switch in renderer_mac).
- Images: local files and remote URLs. Remote fetch with NSURLSession (or
  a worker thread + queue; keep the 32 MB cap from imagehelper.cpp).
- SVG: port svgdoc.cpp against CG shapes + CT text. macOS has no
  ID2D1SvgDocument; parse the SVG elements the app already handles
  (shapes + text runs) and draw them directly. The existing `svgtext.cpp`
  extraction is shared; the drawing is new.
- Mermaid: flowchart, pie, sequence. The layout is shared and golden
  tested; the mac work is a CG painter for the laid-out model
  (LaidOutFlowchart etc.) plus the CT measure seam (`MeasureWithDWrite`
  is Windows-only; add `MeasureWithCoreText` behind the same `MeasureFn`).

**Verify:** mermaid golden JSON is the parity oracle: the mac renderer
draws from the same laid-out coordinates, so geometry mismatches are a
painter bug, not a layout bug. On the Mac, open the fixture files and
compare against the Windows app screenshot. All shared-code changes (if
any) go through the macOS test job first.

**Pitfall:** keep `LayoutCache` equivalent on mac. The hit-testing math
(PointToOffset, u16ToSrc) is portable; only the layout storage differs.
Consider moving the two UTF-8/16 helpers out of layoutcache.cpp into a
pure file so the mac target never needs even the stub header.

## Task 5: Editor parity

- Caret: draw it in CG with a blink timer; reuse the caret-height logic
  (font em height) from the Windows code.
- Selection: selection rects via CT hit testing + the u16ToSrc mapping
  (portable).
- Editing: textbuffer + editcontroller + navigation + undostack +
  formatting + autoformat + inputfilter are the shared core; wire the mac
  view to them (keyboard: keyDown events, modifier detection; mouse:
  mouseDown/dragged/up, double/triple click).
- Clipboard: clipboard_mac.cpp implementing the same signatures with
  NSClipboard. Keep the custom markdown format as a custom pasteboard
  type; keep HtmlToMarkdown and EscapeMarkdown (portable).
- Source view toggle.

**Verify:** on the Mac, edit a file: typing, arrows, selection, undo,
redo, bold/italic/code toggles, autoformat (lists, headings), paste from
other apps. Full test suite green in CI. This is where the shared core
earns its keep: no editor logic is rewritten.

## Task 6: Platform polish

- Menus replacing the ribbon: app menu (About, Settings), Document menu
  (Open, Reload, Save, Save As, Toggle Source, Edit), Format menu (the
  formatting commands), View menu (zoom, wrap, content width).
- Settings: settings_mac.cpp storing the same AppSettings struct as JSON
  in `~/Library/Application Support/MarkDownIt/settings.json`; recent
  files list; welcome screen (port welcomescreen.cpp to CG/CT, reuse the
  card layout math).
- File association: declare document types in the .app bundle's
  Info.plist (CFBundleDocumentTypes). Note: on mac, .md may be claimed by
  other apps; provide "Set as default reader" only if trivial, otherwise
  document the Open With flow.
- crash_trace_mac: same breadcrumb API, log to
  `~/Library/Logs/MarkDownIt/crash_trace.log`.
- Zoom and content width modes wired to the renderer (port the number
  changes; the layout metrics live in the shared theme).

**Verify:** on the Mac, every menu command works; settings survive
restart; zoom and wrap behave like Windows. CI suite green.

---

## Task 7: Packaging

- .app bundle: `MarkDownIt.app/Contents/MacOS/MarkDownIt` +
  `Resources/app.icns` (generate from assets/ or reuse the Windows icon
  art as a 512x512 icns).
- CI: `macos-15-arm64` job builds the bundle and uploads it as an artifact
  (zip of MarkDownIt.app).
- Note on signing: unsigned builds require right-click open
  ("developer cannot be verified"). Fine for personal use. Public
  distribution needs an Apple Developer certificate (cost) and/or a
  Homebrew cask once the binary is stable.

**Verify:** download the artifact on the Mac, right-click open, double-
click a .md through the Open With flow. `file MarkDownIt` shows an arm64
executable; `dmg`/cask deferred.

## Task 8: Parity pass and cleanup

- Walk the Windows app's feature list against the mac app (the
  references/checklist in the wysiwyg editor notes is the feature
  inventory). Find and close gaps: right-click context menu, margin
  selection, F5 reload, window placement memory, dirty-file prompt.
- Remove the `test-macos` stub include path trick if Task 4's helper
  split made it unnecessary; keep the job either way.
- Decide whether to fold the mac seams back into the Windows renderer
  later (optional refactor, not a port requirement).

**Verify:** feature checklist matches; both test suites green.
