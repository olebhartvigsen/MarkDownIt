# Printing: a plan for both ports

*2026-11-15. Plan only. Nothing in this file has been implemented.*

> **For Hermes:** implement task by task. Phase 1 is testable on Linux with
> the portable suite; Phases 2 and 3 need the CI runners and, for the last
> step, a real printer.

## Goal

Ctrl+P on Windows and Cmd+P on macOS open the system print panel and send the
open document to a printer. The paper carries the reading view at 100% zoom:
the same blocks, the same typography and the same light palette, cut into pages
that fit the paper.

## Why this is small

Two pieces already exist.

1. **One shared display list.** `layout::LayoutDocument`
   (`src/layout/break_heading_layout.cpp:119`) walks the document at any
   content width and emits `display::DisplayList`, plain structs with no
   platform handle. Both renderers replay it (`src/renderer.cpp:2766`,
   `src/macos/renderer_mac.cpp:1035`).
2. **One seam for drawing.** `display::Play`
   (`src/layout/display_player.cpp:168`) replays onto any
   `platform::RenderTarget`. `platform::D2DTarget` wraps any
   `ID2D1RenderTarget` (`src/windows/render_target_win.h:32`), so a printer DC
   is already inside the seam. `platform::CoreGraphicsTarget` wraps any
   `CGContext` (`src/macos/cg_target_mac.h:29`), so a print context is too.

What is missing is pagination and two small paint entries that run without the
window's scroll offset, caret and highlight washes. That is the whole feature.

## Scope of V1

V1 prints paragraphs, headings, lists and their markers, quotes, thematic
breaks, fenced code, tables, task checkboxes, links and raster images.

V1 does **not** print Mermaid diagrams or standalone SVG pictures. The layout
reserves their band and emits no display items for them:
`src/layout/svg_mermaid_layout.cpp` says so directly ("Mermaid blocks emit NO
display items: the renderers keep painting the diagrams themselves"), and
`Renderer::ImageHandleFor` answers null for `svg:` urls
(`src/renderer.cpp:834-845`). They print as an empty band until Phase 5.

Also out of V1: page numbers and running headers, print preview, a page setup
UI, booklet or duplex options, printing a selection.

The simplification this buys is worth naming: with no find or marker washes on
paper, the display list's own opaque fills (the code card, the table cells)
are already enough. The print pass is therefore *only* the replay, with no
overlay pass at all. That removes a Windows flag through
`PaintSharedOverlays`, and it removes the risk of the print pass clobbering the
window's hit map (`tableFilterButtons_`, cleared and refilled on every frame at
`src/renderer.cpp:867` and `:881`).

## Decisions the plan fixes

| Decision | Value | Why |
|---|---|---|
| Unit | the seam unit is 1/96 inch (`kPtToDip`, `src/theme.h:84`); paper is converted once at the boundary, `dips = points * kPtToDip` | the layout, the theme and both targets speak DIPs. A 12 pt body line prints at 12 pt, because the theme stores point sizes and multiplies by `kPtToDip` when it builds a font |
| Palette | `BasePalette(ActiveMarkdownStyle())` | `references/night-mode-reference.md` section 24: print uses the document's own appearance, never the night screen |
| Mode | `editing = false`, no selection, no find or marker washes, no pinned table header | print is the reading view |
| Zoom | 1.0; the screen zoom is not a print setting | zoom is baked into layout coordinates |
| Column | the page content width, with no `maxContentWidth` cap | the cap (800 DIP GitHub at `src/theme.h:274`, 720 Apple at `:423`) on a 642 DIP A4 page would leave half the paper blank |
| Page setup | the OS print panel only | no settings UI and no stored print preferences in V1 |
| Source view | printing always prints the rendered document, even when the source view is showing | one meaning for Print; a "print the source" mode is a later question |
| Verification | pagination is unit tested; the print paths are checked by hand | no CI runner has a printer |

## The shared page model

New files `src/layout/print_pages.h` and `src/layout/print_pages.cpp`, added to
`MARKDOWNIT_CORE_SOURCES` in the layout block of `cmake/sources.cmake:21`.

```cpp
// src/layout/print_pages.h
#ifndef MARKDOWNIT_SRC_LAYOUT_PRINT_PAGES_H_
#define MARKDOWNIT_SRC_LAYOUT_PRINT_PAGES_H_

#include "layout/displaylist.h"
#include "layout/document_layout.h"

#include <cstddef>
#include <vector>

namespace layout {

// The paper in seam units (1/96 inch). The platform converts the print
// panel's points once, at the boundary.
struct PrintPage {
    float width = 793.7f;    // A4: 595.28 pt x 96/72
    float height = 1122.5f;  // 841.89 pt x 96/72
    float margin = 75.6f;    // 56.7 pt x 96/72, a 2 cm margin
    float ContentWidth() const { return width - 2.0f * margin; }
    float ContentHeight() const { return height - 2.0f * margin; }
};

// One printed page in layout coordinates. top and bottom are cut lines in
// the layout's own y, so a band may begin and end inside a block.
struct PrintBand {
    float top = 0.0f;
    float bottom = 0.0f;
    size_t firstBlock = 0;  // index into DocumentLayout::blocks
    size_t lastBlock = 0;   // one past the last block the band touches
};

// Cuts the laid out document into bands of ContentHeight(). A block that
// fits a page but not the room left on this one starts the next page. A
// block taller than a page is cut, and continues above the next band.
std::vector<PrintBand> PaginateDocument(const DocumentLayout& laid,
                                        const PrintPage& page);

// The items of the list that intersect the band. Every PushClip and its
// PopClip survive whatever their rect, because the player pairs them and a
// dropped half clips the rest of the page.
display::DisplayList SliceForBand(const display::DisplayList& list,
                                  const PrintBand& band);

}  // namespace layout

#endif  // MARKDOWNIT_SRC_LAYOUT_PRINT_PAGES_H_
```

The cut walk, in words:

- Start a band at `top = 0`, with `i` on the first block.
- If the block's `y` is at or past `top + ContentHeight()`, close the band at
  the block's `y` (the gap before it stays on the closed page) and start a new
  band there. Do not advance `i`.
- If the block's bottom passes `top + ContentHeight()` and the block is
  shorter than a full page and starts below `top`, close the band at the
  block's `y` and start a new band there. Do not advance `i`. This is the
  widow rule: blocks move whole.
- Otherwise the block overflows because it is taller than a page, or because
  it starts exactly at `top`. Close the band at `top + ContentHeight()` and
  advance `top` by one page height. Do not advance `i`.
- If the loop ever closes a band without moving `top`, force one page of
  progress; pagination must terminate on any input.
- When the blocks run out, close the last band at `max(top + ContentHeight(),
  last block bottom)`, so a one page document is still one page.

`firstBlock` and `lastBlock` are then filled by one extra linear pass over the
blocks: the first block whose bottom is past `band.top`, and the first block
whose top is at or past `band.bottom`. They are informational for tests and
for the Windows page range, not needed for drawing.

`SliceForBand` needs the bounds of an item, which does not exist yet.

### Task 2.3: the print job

**Files:** create `src/print_win.h`, `src/print_win.cpp`; add the `.cpp` to
`MARKDOWNIT_WINDOWS_APP_SOURCES` in `cmake/sources.cmake`.

```cpp
namespace print {
// Shows the print panel and prints the document. False when the user
// cancelled or the printer refused the job; message carries the reason in
// UTF-8 for the caller's MessageBox.
bool PrintDocument(HWND owner, const std::wstring& documentName,
                   std::string* message);
}
```

The steps, in order:

1. `PrintDlgExW` with `PD_RETURNDC | PD_USEDEVMODECOPIESANDCOLLATE |
   PD_NOSELECTION`, `hInstance` from the app. The user cancels, or the dialog
   returns a DC. Free the `DEVMODE` and the `DEVNAMES` with the same
   `hDevMode`/`hDevNames` block the dialog hands back.
2. Page geometry from the DC, not from `DEVMODE`:
   `pageWidthPt = GetDeviceCaps(hdc, PHYSICALWIDTH) * 72 / LOGPIXELSX`, and the
   same with `PHYSICALHEIGHT` and `LOGPIXELSY`. The printable margins come
   from `PHYSICALOFFSETX/Y` and `HORZRES`/`VERTRES`, in the same conversion,
   with a floor of 0.5 inch on each side so text never sits on the edge.
   Landscape needs no special case: the DC already reports the page the way the
   driver will print it.
3. Ask the renderer for `PrintLayout` with `contentWidthDip = contentWidthPt *
   kPtToDip`, and `PaginateDocument`.
4. Add `ID2D1Factory* Renderer::Factory() const` (the renderer already holds
   one) and create an `ID2D1DCRenderTarget` with
   `D2D1_RENDER_TARGET_PROPERTIES{D2D1_RENDER_TARGET_TYPE_SOFTWARE,
   {DXGI_FORMAT_B8G8R8A8_UNORM, D2D1_ALPHA_MODE_IGNORE}, printerDpiX,
   printerDpiY, D2D1_RENDER_TARGET_USAGE_NONE,
   D2D1_FEATURE_LEVEL_DEFAULT}`. Software is not a fallback; a DC target has no
   hardware path worth having on a printer.
5. `StartDocW` with a `DOCINFOW` that carries the document name, then for each
   band in the requested range: `StartPage`, `rt->BindDC(hdc, &pageRect)` with
   the page rect in device pixels, clear the page white through GDI
   (`PatBlt` with `WHITE_BRUSH`) because the target ignores alpha, `BeginDraw`,
   `RenderPrintBand`, check the `HRESULT`, `EndDraw`, `EndPage`.
6. `EndDoc` on success, `AbortDoc` on a cancel from the `SetAbortProc`
   callback, and `DeleteDC` in every path. Report `BeginDraw`/`EndDraw`
   failures as one message and stop, rather than printing blank pages.
7. Copies: with `PD_USEDEVMODECOPIESANDCOLLATE` set, the driver prints
   `nCopies`. Repeat the page loop only when the dialog clears the flag.

The transform the print job hands to `RenderPrintBand`:

```cpp
const float s = printerDpiY / 96.0f;   // device pixels per DIP
const D2D1_MATRIX_3X2_F transform =
    D2D1::Matrix3x2F::Scale(s, s) *
    D2D1::Matrix3x2F::Translation(originXDip * s,
                                  (originYDip - bandTop) * s);
```

so a point at layout `(x, y)` lands at device
`((x + originX) * s, (y + originY - bandTop) * s)`. Verify the top margin on
the first print; a margin that is `s` times too small means the translation was
applied before the scale.

### Task 3.2: the print job

**Files:** create `src/macos/print_mac.h`, `src/macos/print_mac.mm`. Add
`"-framework PDFKit"` to the mac app target's frameworks
(`CMakeLists.txt:718-723`).

The route is a PDF, because PDFKit then owns page ranges, copies and the panel:

1. Run `[[NSPrintPanel printPanel] runModalWithPrintInfo:info]`. Cancelled, or
   an `NSPrintInfo`.
2. Paper geometry from `[info imageablePageBounds]`, which already has the
   user's margins removed: convert its size and origin to DIPs with
   `kPtToDip` and hand the content width to `PrintLayout`.
3. Create an in-memory PDF: `CGDataConsumerCreateWithCFData` and
   `CGPDFContextCreate` at the paper size in points.
4. Per band: `CGContextBeginPage(ctx, &mediaBox)`, then set the page transform
   once. PDF space is bottom left with y up; the seam is top left with y down:

   ```objc
   CGContextTranslateCTM(ctx, 0, pageHeightPt);
   CGContextScaleCTM(ctx, 72.0 / 96.0, -72.0 / 96.0);
   CGContextTranslateCTM(ctx, originXDip, originYDip - band.top);
   ```

   Then `platform::CoreGraphicsTarget target(ctx)` and
   `RenderPrintBand(&target, slice)`, then `CGContextEndPage(ctx)`. The last
   translate carries the band, so wrap the whole block in
   `CGContextSaveGState` / `CGContextRestoreGState` rather than undoing it by
   hand.
5. Close the context, build a `PDFDocument` from the `NSData`, and run
   `[pdf printOperationForPrintInfo:info scalingMode:kPDFPrintPageScaleNone
   autoRotate:NO]` with `[op runOperation]`.

Two things to check on the first run, both visible immediately: upside down
output means the flip pair is in the wrong order, and a page that is 1.33
times too big means the scale was dropped.

5. **Print preview** (a page view of the same bands) and **print scale**

## Risks

1. **The 0.75 factor.** If the DIP to point conversion is applied twice or not
   at all, every page is 1.33 times too big or too small, and it looks like a
   layout bug rather than a unit bug. Check: a body line measures 16 seam units
   and must print at 12 pt. Measure one line on paper, not the page count.
2. **A printer driver that refuses a Direct2D DC target.** Use
   `D2D1_RENDER_TARGET_TYPE_SOFTWARE` and `D2D1_ALPHA_MODE_IGNORE`, clear the
   page white through GDI first, and treat a failed `BeginDraw` as an error
   message, not as a blank page.
3. **Very tall blocks are cut mid-line in V1.** A table row can be cut in half.
   This is the known cost of the simple rule; Phase 5 removes it. Say so in
   `references/printing.md` rather than leaving it to be discovered.
4. **Clip pairs.** Dropping a `PushClip` whose rect is off the band, and
   keeping its `PopClip`, breaks the player's pairing and can clip the rest of
   the page. Keep both, always.
5. **The page count and the page range must agree.** The layout runs after the
   dialog, never before, so the range the user picked and the bands that exist
   come from the same paper size.
6. **Copy count.** With `PD_USEDEVMODECOPIESANDCOLLATE`, the driver owns the
   copies. Looping as well prints `nCopies` squared pages.
7. **Cost on a long document.** Slicing is O(items) per page. A 300 page
   document with 10k items is 3M bounds tests, which is fast enough; bucket by
   y only if it ever shows.
8. **macOS ordering.** The panel must run before the layout, or the first page
   count is computed from the wrong paper. Running the panel inside
   `NSPrintOperation` asks for pages before the layout exists.

## Open questions

1. Should the printed body follow the theme's point size (12 pt for GitHub,
   10.5 for Apple), or fill the page more aggressively? V1 keeps the theme
   size, which is what "the reading view at 100%" means.
2. Should Print also appear on a ribbon tab, or only in the application menu
   next to the export commands? V1 follows `cmdExportPdf` and stays in the
   menu.
3. Should a CSV table document be printable? It parses into table nodes, so it
   is by construction. Decide whether the doc name and the page footer say
   "CSV" or the file's own name; V1 uses the file name.
4. Print from the source view prints the rendered document (see the decision
   table). If readers expect the source text, that becomes a second command
   later, not a toggle.

### Deviations from the steps

- **2.2 and 2.3, no band pass inside the frame's `Render`, and no separate
  `print_page_paint.*`.** The drivers ask for the page's layout and play its
  slice themselves, through the same walk and the same `display::Play` the
  window uses. Putting the band pass in `Render` would have given the window's
  paint loop a job printing does not need, and a wrapper around one player
  call is a file to keep in step with the player rather than a seam.
- **2.6, the capture state reports numbers instead of drawing page pictures
  into the frame.** Drawing two pages into the window would have needed an
  offscreen picture per port, which is the one thing this plan deliberately
  avoids; the numbers plus the mac PDF prove the same thing without it. The
  PDF is uploaded with the mac capture artifact.
- **The classic print panel instead of `PrintDlgEx`.** The extended panel's
  page range is not read, and its struct is declared behind a version guard
  the project does not set. Naming `WINVER` to satisfy it hid Direct2D 1.3's
  interfaces in the same translation unit.
- **Ctrl-P works in view mode.** The Windows view-mode key gate now lets a key
  through when the command state says its command can act, which is the same
  answer the ribbon reads.

### What is still open

The gaps recorded in `references/printing.md` stand: a Mermaid diagram and an
SVG fence print as empty bands, an inline image is not resolved onto the page,
there is no page number, and a block taller than a page is cut through its
line. Each is a missing picture, never a wrong one. The open questions above
were answered the way the plan proposed: the theme's own point size, the menu
beside the export commands, the file's name on the job, and the rendered
document even from the source view.
